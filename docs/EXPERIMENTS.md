# Эксперименты

Все числа получены программой `cmd/stegobench` (07.11.2026, Ryzen 5 5600X,
Windows 10, Go 1.26.4). Как повторить — в конце документа.

## Данные

17 фотографий из обоев Windows (`C:\Windows\Web\Wallpaper\Theme1`, `Theme2`,
`C:\Windows\Web\Screen`). Исходники — JPEG, поэтому каждая уменьшена вдвое
усреднением блоков 2×2: это стирает следы JPEG-сжатия, на которые иначе
реагируют детекторы. Получилось 17 изображений (14 — 960×600, 2 — 1920×600,
1 — 1920×1080) и 140 цветных фрагментов 256×256.

Фотографий мало, поэтому оценки AUC — грубые (±0,05). Для выводов о
скрытности против современных детекторов (SRM + ансамбль, нейросети) нужен
набор вроде BOSSbase (10 000 изображений); здесь показана тенденция.

## 1. Скрытность

**Способы.** Для сравнения реализованы:

- **v2: 3-2-3, замена** — прежняя программа: байт сообщения в случайном
  пикселе, 3 младших бита R, 2 — G, 3 — B заменяются битами байта;
- **записка: R/B, замена** — схема из записки НИР: бит в младший бит R или B
  случайного пикселя;
- **±1 без STC** — ±1 в случайных элементах, без учёта текстуры;
- **v3** — новая программа на трёх уровнях устойчивости.

**Нагрузка** — бит сообщения на элемент (канал пикселя). Для v3 это
шифротекст с имитовставкой; код Рида–Соломона и заголовок — сверху, поэтому
v3 меняет изображение при той же полезной нагрузке.

**Детекторы**: χ² (Westfeld, Pfitzmann, 1999), RS-анализ (Fridrich, Goljan,
Du, 2001), SPA (Dumitrescu, Wu, Wang, 2003) — оценивают долю элементов с
заменённым младшим битом; **SPAM+ЛДФ** — обучаемый: 100 признаков
совместной встречаемости остатков первого и второго порядка (упрощённый
SPAM, Pevný, Bas, Fridrich, 2010) и дискриминант Фишера, 10-кратная
перекрёстная проверка; он видит и ±1. **AUC** — вероятность, что детектор
поставит стегоизображению оценку выше, чем пустому: 0,5 — не отличает,
1,0 — отличает всегда.

Выводы:

1. **Замена младшего бита обнаруживается.** Метод из записки при нагрузке
   0,05 бита на элемент выявляется RS/SPA с AUC 0,82–0,84, при 0,1 — 0,93–0,94,
   при 0,2 — 1,00. Оценки RS/SPA (0,114 и 0,113 при нагрузке 0,1, на пустых
   — 0,014) почти равны доле элементов с сообщением: детектор не только
   находит сообщение, но и измеряет его длину.
2. **±1 обманывает классические детекторы** (AUC RS/SPA ≤ 0,56 при любой
   нагрузке), но не обучаемый: SPAM+ЛДФ — 0,84 при 0,05 и 0,89 при 0,1.
3. **v3 «обычная» (STC + HILL) — самая скрытная.** SPAM+ЛДФ: 0,53 при 0,01,
   0,60 при 0,05, 0,65 при 0,1 — против 0,65 / 0,84 / 0,89 у ±1 без STC.
   Изменений почти вдвое меньше (2,9 % против 5,0 % при 0,1), PSNR выше.
4. **χ² бесполезен** при случайном расположении сообщения (AUC 0,50–0,53):
   он рассчитан на последовательное встраивание с начала изображения.
5. **Цена устойчивости — скрытность.** «Повышенная» и «максимальная» видны
   SPAM+ЛДФ (AUC 0,70–0,79 уже при 0,005–0,01). На фрагменте 256×256 главный
   след — устойчивый заголовок: ≈1050 неадаптивных изменений (0,5 %
   элементов). На большом изображении он размывается.
6. **PSNR/SSIM не отражают скрытность**: у всех способов PSNR > 50 дБ и
   SSIM > 0,997 — глазом изменения не видны, а детекторы различают.

## 2. Устойчивость

Встраивается сообщение из 254 символов (не из корпуса сжатия), затем
изображение портится: **закраска** — прямоугольник заданной доли площади
заливается цветом своего центра; **шум** — ±1 в заданной доле случайных
элементов (слабая обработка). По 3 опыта на каждое из 17 изображений.

В ячейке — доля успешных извлечений, %; в скобках — доля случаев, когда
прочитан заголовок (программа понимает, что сообщение есть, и говорит
«повреждено», а не «не найдено»). Столбцы, подписанные «обычная»,
«повышенная», «максимальная», — выбранные параметры уровней; остальные —
варианты, из которых выбирали.

Выводы:

1. **STC с большим w не переживает почти ничего** (закраска 0,5 % — 6 %
   успеха): бит сообщения зависит от ≈4,5·w элементов, порча любого из них
   портит бит, и ошибок становится больше, чем исправляет код.
2. **Устойчивость дают малые w и h = 1** (бит = чётность группы из w
   элементов; порча элемента портит ровно один бит) и **избыточность RS**.
   Уменьшение w с 8 до 4 при RS 64 подняло успех при закраске 1 % с 8 до 88 %.
3. Выбранная «лестница»: **обычная** — канал без потерь; **повышенная** —
   до ≈1 % закрашенной площади или ±1 в 0,5 % элементов; **максимальная** —
   до 5 % площади или ±1 в 2 % элементов.
4. **Устойчивый заголовок** читается и при закраске 10 % (100 %), и при
   шуме 5 % (100 %) — сообщение уже не восстановить, но программа говорит,
   что оно было.
5. Число изменений у устойчивых уровней на этом сообщении — ≈1800–2100
   против 330 у «обычной»: вот почему они заметнее (раздел 1).

## 3. Шифры

Скорость шифрования с имитовставкой, один поток:

| Режим | Ключ, бит | Nonce, байт | Имитовставка, байт | 64 Б, МБ/с | 1024 Б, МБ/с | 16384 Б, МБ/с |
|---|---|---|---|---|---|---|
| Кузнечик-MGM | 256 | 16 | 16 | 32.3 | 46.2 | 47.4 |
| Ascon-AEAD128 | 128 | 16 | 16 | 272.0 | 517.7 | 553.4 |
| Магма-MGM | 256 | 8 | 8 | 24.6 | 29.8 | 30.2 |
| Кузнечик-MGM, прежний Encrypt | 256 | 16 | 16 | 0.01 | 0.02 | — |

Ascon-AEAD128 быстрее «Кузнечика» с MGM в 12 раз, «Магмы» с MGM — в 18 раз,
и требует 128-битного ключа. «Магма» с MGM медленнее «Кузнечика» в 1,6 раза:
при 64-битном блоке шифр и умножение в поле вызываются вдвое чаще.
Имитовставка у Магмы-MGM — 8 байт. Для текстовых сообщений (килобайты)
все три режима работают за доли миллисекунды; главное время уходит на
Argon2id (≈0,03–0,2 с) и STC.

Исправленный интерфейс MGM быстрее прежнего `Encrypt` более чем в 2000 раз:
прежний разворачивал ключ «Кузнечика» на каждом блоке.

## Как повторить

```bash
go run ./cmd/stegobench prepare -out data -src "C:/Windows/Web/Wallpaper/Theme1,C:/Windows/Web/Wallpaper/Theme2,C:/Windows/Web/Screen"
go run ./cmd/stegobench detect -data data/tiles -out results
go run ./cmd/stegobench robust -data data/full -out results
go run ./cmd/stegobench ciphers -out results
go run ./cmd/stegobench compress -out results -text записка.txt
```

Случайность в опытах детерминирована (зерно — номер изображения, способа и
нагрузки), поэтому результаты повторяются на тех же данных. Стенд
`detect` идёт около минуты, `robust` — секунды.
